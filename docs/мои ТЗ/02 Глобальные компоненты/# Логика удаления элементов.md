# **SYSTEM: Soft Delete Policy**

---

# 1. Цель

Определить единый стандарт удаления данных в системе.

---

# 2. Основной принцип

В системе НЕ существует физического удаления данных через UI.

Любое удаление:

→ это всегда soft delete  
→ данные сохраняются в базе  
→ доступ к ним может быть восстановлен через backend/БД

---

# 3. Модель удаления

---

## 3.1 Общий подход

Любая сущность поддерживает поле:

is_deleted: boolean

или расширенный вариант:

deleted_at: datetime | null
deleted_by: string | null

---

## 3.2 Рекомендуемый стандарт

is_deleted: boolean
deleted_at: datetime
deleted_by: string

---

# 4. Поведение системы

---

## 4.1 Удаление через UI

Любая операция "Удалить":

- НЕ вызывает DELETE entity
- выполняет:

PATCH /{entity}/{id}
 {
 is_deleted: true
 }

---

## 4.2 Скрытие данных

По умолчанию:

- все GET запросы возвращают только:

is_deleted = false

---

## 4.3 Админ режим (опционально)

Администратор может видеть удалённые записи:

- через фильтр:
  - include_deleted = true

---

# 5. API правила

---

## 5.1 Запрещено

DELETE /entity/{id}

запрещено использовать в UI

---

## 5.2 Разрешено

PATCH /entity/{id}

с установкой:

is_deleted = true

---

# 6. Восстановление данных

---

## 6.1 Возможность восстановления

Администратор может восстановить запись:

PATCH /entity/{id}
 {
 is_deleted: false
 }

---

## 6.2 Источник истины

Восстановление всегда происходит:

- через backend
- либо напрямую через БД (fallback)

---

# 7. UI поведение

---

## 7.1 Кнопка "Удалить"

- НЕ удаляет запись физически
- вызывает soft delete
- может отображаться как:
  - "Удалить"
  - или "Деактивировать" (рекомендуется для UX)

---

## 7.2 Состояния

### Активная запись:
- отображается в списках

### Удалённая:
- скрыта по умолчанию

---

# 8. Audit trail

---

При удалении сохраняется:

- deleted_at
- deleted_by

---

# 9. Безопасность

---

- удаление доступно только admin
- backend обязан игнорировать попытки hard delete
- frontend НЕ может управлять типом удаления

---

# 10. Ограничения

---

- запрещено физическое удаление через API UI слоя
- запрещено каскадное удаление без soft delete логики
- запрещено обходить is_deleted фильтр без явного флага

---

# 11. Связь с системой

---

Используется во всех сущностях:

- Products
- Clients
- Suppliers
- Colors
- Sizes
- Product Types
- И других списках системы, с которыми работают пользователи

---

# 12. Итог

Soft Delete Policy обеспечивает:

- безопасность данных
- возможность восстановления
- контроль истории изменений
- защиту от случайных удалений
