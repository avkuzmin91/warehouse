# Спецификация UX/UI для поля выбора даты (без времени)

## Область применения

Поле используется для выбора **одной календарной даты без времени**:

- дата доставки
- дата рождения
- дата бронирования
- любые атрибуты с типом Date

------

# 1. Базовый паттерн

Используется:
→ **input + date picker (календарь)**

### Почему

- исключает ошибки формата
- быстрее ручного ввода
- привычный паттерн

------

# 2. Структура компонента

## 2.1 Поле ввода

- Формат отображения: `DD.MM.YYYY` (локализуемый)
- Плейсхолдер: `дд.мм.гггг`
- Иконка календаря справа
- Кнопка очистки (×) при наличии значения

Пример:

[ 12.03.2026 📅 × ]

------

## 2.2 Date picker (календарь)

Открывается:

- по клику на поле
- по клику на иконку

Отображает:

- месяц + год
- сетку дней (7 колонок)

------

# 3. Поведение

## 3.1 Выбор даты

- Клик по дню:
  → выбирает дату
  → закрывает календарь
  → подставляет значение в input

------

## 3.2 Навигация

- Переключение месяцев (← →)
- Быстрый выбор года/месяца (dropdown или переключение вида)

------

## 3.3 Ограничения (если есть)

Поддержка:

- minDate (минимальная дата)
- maxDate (максимальная дата)
- disabledDates (конкретные даты)

Недоступные даты:

- визуально задизейблены
- не кликабельны

------

## 3.4 Очистка

- Клик по «×» очищает значение
- aria-label: «Очистить дату»

------

## 3.5 Ручной ввод (опционально)

Если включён:

- Маска: `DD.MM.YYYY`
- Автоподстановка разделителей
- Валидация при вводе
- Невалидная дата → ошибка

Если выключен:

- поле readonly

------

# 4. Валидация

Ошибки:

- неверный формат
- несуществующая дата (31.02)
- вне допустимого диапазона

Отображение:

- текст ошибки под полем
- подсветка поля

------

# 5. Клавиатура

- Enter → открыть календарь
- Esc → закрыть
- Tab → переход
- Стрелки → навигация по дням (если открыт календарь)

------

# 6. Доступность (Accessibility)

- role="textbox" + aria-haspopup="dialog"
- календарь = dialog / grid
- дни = button
- aria-selected для выбранной даты
- поддержка screen reader

------

# 7. Мобильная версия

- Bottom sheet или нативный picker (если допустимо)
- Крупные зоны нажатия (≥ 44px)
- Фиксированная панель:
  - «Отмена»
  - «Применить» (если выбор не мгновенный)

------

# 8. Улучшения (опционально)

## 8.1 Быстрые действия

- Сегодня
- Завтра
- +7 дней

------

## 8.2 Подсветка

- текущий день (today)
- выбранный день
- hover диапазон

------

# 9. Антипаттерны

- Только ручной ввод без календаря
- Нет валидации
- Сложный выбор года (по одному месяцу листать 20 лет)
- Маленькие кликабельные зоны

------

# 10. Переиспользуемость

Пропсы:

- value: Date | null
- onChange: (date: Date | null) => void
- minDate?: Date
- maxDate?: Date
- disabledDates?: Date[]

Дополнительно:

- locale
- format
- readonly

------

# 11. Форматы

Рекомендуемый:

- RU: DD.MM.YYYY
- EN: MM/DD/YYYY или ISO (YYYY-MM-DD)

Хранение:
→ ISO 8601 (`YYYY-MM-DD`)

------

# 12. Технологии

- React
- date-fns / dayjs
- Headless UI или кастомный календарь

------

# 13. Резюме

→ Использовать input + календарь

Даёт:

- точность
- удобство
- контроль формата
- переиспользуемость

### Источник: `# Поле единичного выбора.md`

# Спецификация UX для одиночного выбора из справочников (цвета, размеры и др.)

## Область применения

Единый паттерн для выбора **одного значения** из большого справочника (50–500+ элементов):

- Цвета (названия)
- Размеры (S, M, L, EU 42 и т.д.)
- Любые другие атрибуты с фиксированным списком

Цель: быстрый поиск, точность выбора, переиспользуемость компонента.

------

# 1. Базовый паттерн

Используется **autocomplete (combobox) с одиночным выбором**.

### Почему

- Быстрее, чем скроллить длинные списки
- Минимизирует ошибки
- Компактен в карточке товара

------

# 2. Структура компонента

## 2.1 Поле ввода

- Плейсхолдер: «Выберите значение…» / «Начните вводить…»
- Текущее выбранное значение отображается как текст
- Есть кнопка очистки (×) внутри поля

Пример:

[ Medium × ]

### Очистка значения

- Клик по «×» очищает текущее значение
- Кнопка всегда видна при наличии выбранного значения
- Размер кликабельной зоны ≥ 24px (лучше 32px для мобильных)
- Имеет hover/active состояния
- Должна быть доступна с клавиатуры (tab focus + Enter/Space)
- aria-label: «Очистить значение»

------

## 2.2 Выпадающий список (dropdown)

- Открывается по клику/фокусу/вводу
- Фильтруется в реальном времени
- Скроллируемый

Элемент списка:

( ) Small
(●) Medium
( ) Large

- Выбранный элемент подсвечен

------

# 3. Поведение

## 3.1 Выбор

- Только одно значение
- Выбор закрывает список
- Значение подставляется в поле

## 3.2 Поиск

- Без учёта регистра
- Поддержка частичных совпадений
- Debounce 150–300 мс

## 3.3 Клавиатура

- ↑ ↓ — навигация
- Enter — выбрать
- Esc — закрыть
- Backspace — очистить значение

------

# 4. Производительность

- Объём: 50–500+ элементов
- Виртуализация при больших списках
- Не рендерить всё сразу

------

# 5. Доступность (Accessibility)

- Роль: combobox
- Список: listbox
- Элементы: option
- Поддержка screen reader
- Управление фокусом

------

# 6. Мобильная версия

- Bottom sheet или fullscreen список
- Крупные элементы (≥ 44px)
- Поле поиска сверху

------

# 7. Улучшения (опционально)

## 7.1 Группировка

Пример (размеры):

- Стандартные
- Расширенные
- Числовые

## 7.2 Популярные значения

Показывать сверху

## 7.3 Недавние

Последние выбранные значения

## 7.4 Сортировка

- По алфавиту
- По логике (S → M → L)

------

# 8. Антипаттерны

- Обычный select без поиска
- Длинный список без фильтрации
- Нет возможности очистить значение
- Потеря выбранного значения при вводе

------

# 9. Переиспользуемость

Пропсы компонента:

- options: string[]
- value: string | null
- onChange: (value: string | null) => void

Дополнительно:

- groups
- popularOptions
- recentOptions

------

# 10. Особенности по типам

| Аспект       | Цвета        | Размеры          |
| ------------ | ------------ | ---------------- |
| Визуализация | Не требуется | Не применяется   |
| Сортировка   | Алфавит      | Логическая       |
| Поиск        | По названию  | Название + числа |

------

# 11. Примеры

## Цвета

Ввод: «nav» → Navy

## Размеры

Ввод: «4» → 42

------

# 12. Технологии

- React
- Tailwind
- react-window (при необходимости)

------

# 13. Резюме

→ Использовать autocomplete (combobox) с одиночным выбором

Обеспечивает:

- скорость выбора
- точность
- масштабируемость
- переиспользование

### Источник: `# Поле мульти выбора.md`

# Спецификация UX для мультиселекта справочников (цвета, размеры и др.)

## Область применения

Документ описывает единый UX-паттерн для выбора значений из больших справочников (100–500+ элементов), например:

- Цвета (только названия)
- Размеры (S, M, L, EU 42, XL Tall и т.д.)
- Любые другие атрибуты с фиксированным списком

Цель: переиспользуемый, масштабируемый и консистентный компонент.

------

# 1. Базовый паттерн

Используется **мультиселект с автодополнением (autocomplete) + chips**.

### Почему

- Масштабируется на большие списки
- Быстрый поиск через ввод
- Компактно помещается в карточке
- Универсален для разных атрибутов

------

# 2. Структура компонента

## 2.1 Поле ввода

- Плейсхолдер: «Начните вводить…» / «Выберите значения…»
- Поле одновременно является поиском
- Внутри отображаются выбранные значения в виде chips

Пример:

[ M × ] [ L × ] [ XL × ] | Начните вводить…

------

## 2.2 Выпадающий список (dropdown)

- Открывается по клику/фокусу
- Фильтруется в реальном времени
- Скроллируемый

Элемент списка:

☐ Small
☐ Medium
☐ Large

------

## 2.3 Chips (выбранные значения)

- Отображаются внутри поля
- Удаляются по клику на «×» или Backspace

------

# 3. Поведение

## 3.1 Выбор

- Мультивыбор (toggle)
- Список **не закрывается** после выбора
- Поисковый запрос **не очищается**

## 3.2 Поиск

- Без учёта регистра
- Поддержка частичных совпадений
- Debounce 150–300 мс

## 3.3 Клавиатура

- ↑ ↓ — навигация
- Enter — выбрать
- Esc — закрыть
- Backspace — удалить последний chip

------

# 4. Производительность

- Объём: 100–500+ элементов
- Обязательна виртуализация (например, react-window)
- Нельзя рендерить весь список сразу

------

# 5. Доступность (Accessibility)

- Роль поля: combobox
- Список: listbox
- Элементы: option
- Читабельные текстовые лейблы
- Управление фокусом

------

# 6. Мобильная версия

- Полноширинный dropdown или bottom sheet
- Тач-таргеты ≥ 44px
- При необходимости — фиксированная панель действий

------

# 7. Улучшения (опционально)

## 7.1 Группировка

Пример (размеры):

- Стандартные (S, M, L)
- Расширенные (XL, XXL)
- Числовые (40, 41, 42)

## 7.2 Популярные значения

Показывать часто используемые сверху

## 7.3 Недавние

Сохранять последние выбранные

## 7.4 «Очистить всё»

Кнопка сброса выбора

------

# 8. Антипаттерны

- Отсутствие поиска
- Закрытие списка после каждого выбора
- Потеря выбранных значений при фильтрации
- Нет поддержки клавиатуры
- Только визуальное представление без текста

------

# 9. Переиспользуемость

Компонент должен быть универсальным.

Пропсы:

- options: string[]
- selected: string[]
- onChange: (values: string[]) => void

Дополнительно (опционально):

- groups
- popularOptions
- recentOptions

------

# 10. Особенности для разных атрибутов

| Аспект       | Цвета          | Размеры                |
| ------------ | -------------- | ---------------------- |
| Визуализация | Не обязательна | Не применяется         |
| Сортировка   | По алфавиту    | Логическая (S → M → L) |
| Поиск        | По названию    | По названию и числам   |

------

# 11. Примеры использования

## Цвета

Ввод: «nav» → Navy, Navaho White

## Размеры

Ввод: «4» → 40, 41, 42, 44

------

# 12. Технологии

- React
- Tailwind
- react-window (виртуализация)

------

# 13. Резюме

Используется единый паттерн:

→ Мультиселект с автодополнением + chips

Даёт:

- масштабируемость
- производительность
- консистентность между полями
- возможность переиспользования

# **COMPONENT: Date Range Filter**

------

# 1. Цель

Реализовать фильтр по диапазону дат:

- от (date_from)
- до (date_to)

Используется для фильтрации данных по периоду.

------

# 2. Область применения

Используется в:

- FiltersPanel
- list-страницах (таблицы)
- отчётах

------

# 3. UI

Фильтр состоит из двух полей:

1. Дата "с"
2. Дата "по"

------

## 3.1 Тип полей

- date picker
- формат отображения: `DD.MM.YYYY`

------

## 3.2 Placeholder

- "С даты"
- "По дату"

------

## 3.3 Расположение

- в одной строке
- логически объединены в один фильтр

------

# 4. Query State

Фильтр хранится в query params:

```
date_from=YYYY-MM-DD
date_to=YYYY-MM-DD
```

------

## Пример:

```
/products?date_from=2026-01-01&date_to=2026-01-31
```

------

# 5. Поведение

------

## 5.1 Изменение значений

При изменении:

- обновляется Query State
- выполняется API запрос

------

## 5.2 Частичное заполнение

Допускается:

- только date_from
- только date_to

------

### Логика:

- date_from → >= дата
- date_to → <= дата

------

## 5.3 Валидация

Если:

```
date_from > date_to
```

→ ошибка:

- сообщение: "Неверный диапазон дат"
- запрос НЕ отправляется

------

## 5.4 Очистка

При сбросе фильтров:

- date_from очищается
- date_to очищается

------

# 6. API

Передача в запросе:

```
{
  "date_from": "YYYY-MM-DD",
  "date_to": "YYYY-MM-DD"
}
```

------

# 7. UX правила

- значения сохраняются при перезагрузке (через Query State)
- при возврате на страницу фильтр восстанавливается
- debounce НЕ применяется (выбор через picker)

------

# 8. Ограничения

- нельзя вводить дату вручную (если используешь strict picker)
- timezone должен быть единый (обычно UTC или backend standard)

------

# 9. Итог

Date Range Filter — стандартный компонент фильтрации по периоду, полностью интегрированный с:

- Query State Management
- FiltersPanel
- API filtering
