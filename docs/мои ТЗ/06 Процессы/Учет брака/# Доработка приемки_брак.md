# Задача

Необходимо внести изменения в существующую WMS-логику поступлений и изменить статусную модель для поддержки процесса проверки товара на брак.

Перед выполнением задачи изучи существующие документы проекта:

- процессы поступлений
- процессы остатков
- процессы отгрузок
- существующие UI-паттерны
- существующие правила статусных моделей

Важно сохранить текущую архитектуру и стиль документации.

Не создавать новую сущность поступления.
Не изменять существующие паттерны без необходимости.
Изменения должны быть минимальными и являться доработкой текущей логики.

---

# Текущий процесс

Сейчас используется модель:

```text
Ожидает поступления
↓
Принят
```

Логика:

1. Менеджер планирует поступление
2. Создает поступление
3. Указывает количество
4. Товар приезжает
5. Нажимает "Принять на склад"
6. Товар попадает в остатки

Проблема:

Система не поддерживает процесс проверки товара на брак.

После приемки невозможно:

- учитывать непроверенный товар
- фиксировать брак
- выполнять частичную проверку
- отделять годный товар от товара на проверке

---

# Новая бизнес-логика

После физической приемки товара требуется отдельный этап проверки качества.

Новая статусная модель:

```text
Ожидает поступления
↓
Ожидает проверки
↓
Частично проверено
↓
Проверено
```

---

# Описание статусов

## Ожидает поступления

Статус планирования.

Поступление создано, но товар физически еще не поступил.

---

## Ожидает проверки

Статус означает:

- товар физически поступил
- приемка завершена
- товар добавлен на склад
- товар еще не проверен

После перехода в статус:

весь объем поступления должен попадать в состояние:

```text
Не проверено
```

Товар нельзя отгружать.

---

## Частично проверено

Статус означает:

проверена только часть товара.

Пример:

Поступило:

100

Проверено:

60

Осталось:

40

Допускается многократная проверка.

Пример:

100

→ проверили 20

→ потом 30

→ потом 50

---

## Проверено

Весь товар проверен.

Количество "Не проверено" должно быть равно:

```text
0
```

---

# Требования к переходам

Разрешены только:

```text
Ожидает поступления
↓
Ожидает проверки
↓
Частично проверено
↓
Проверено
```

Также допустим переход:

```text
Частично проверено
↓
Частично проверено
```

для повторных проверок.

Запрещено:

- переходить через статус
- выбирать статус вручную
- изменять статус напрямую

Изменение статусов возможно только через бизнес-действия.

---

# Требования к кнопкам

Для статуса:

## Ожидает поступления

Кнопки:

- Редактировать
- Отменить
- Принять на склад

Кнопка:

"Принять на склад"

должна:

- принять товар
- обновить остатки
- перевести статус:

```text
Ожидает поступления
↓
Ожидает проверки
```

---

## Ожидает проверки

Кнопки:

- Провести проверку
- Редактировать

После завершения проверки:

если осталось непроверенное количество:

```text
непроверено > 0
```

перевести:

```text
Частично проверено
```

иначе:

```text
Проверено
```

---

## Частично проверено

Кнопки:

- Продолжить проверку
- Редактировать

После проверки:

если:

```text
непроверено = 0
```

перевести:

```text
Проверено
```

иначе статус не менять.

---

## Проверено

Кнопки:

- Просмотр результатов проверки
- Просмотр брака

Редактирование проверки запрещено.
