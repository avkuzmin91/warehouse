# Задача

Необходимо доработать существующий модуль отгрузок для поддержки отдельной отгрузки брака.

Перед выполнением задачи изучи:

- процессы отгрузок
- процессы поступлений
- процессы остатков
- статусную модель поступлений
- существующие формы создания отгрузок
- существующие таблицы отгрузок
- существующие UI компоненты
- List Page Pattern
- Entity Page Pattern
- таблицы остатков

Использовать существующую архитектуру проекта.

Не создавать новый модуль.
Не создавать отдельную сущность "Отгрузка брака".
Не ломать существующую модель отгрузок.

Необходимо расширить текущую логику.

---

# Контекст

После внедрения проверки качества в системе появились новые типы складских остатков:

- Годный товар
- Брак
- Не проверено

Сейчас система позволяет отгружать только общий остаток.

Проблема:

Брак также должен отгружаться со склада.

Примеры:

- возврат клиенту
- вывоз брака
- возврат поставщику
- отдельная логистика брака
- утилизация

При этом брак нельзя смешивать с обычной отгрузкой.

---

# Новая бизнес-логика

Необходимо разделить типы отгрузки:

```text
Отгрузка
    ↓

Тип товара:

[ Годный ]
[ Брак ]
```

Тип отгрузки определяет источник остатков.

---

# Новое поле

Добавить поле:

```ts
тип_остатка
```

Допустимые значения:

```ts
ГОДНЫЙ
БРАК
```

Описание:

ГОДНЫЙ:

использует остаток годного товара

БРАК:

использует остаток брака

---

# Изменение формы создания отгрузки

Сейчас:

```text
Товар

Количество
```

Новая структура:

```text
Товар

Тип отгрузки

[ Годный ] [ Брак ]

Остатки:

Годный: 92
Брак: 8
Не проверено: 0

Количество
```

---

# UI требования

Тип отгрузки не использовать через select.

Использовать:

- сегмент-контрол
- переключатель
- группу кнопок

Пример:

```text
[ Годный ] [ Брак ]
```

Активный вариант должен быть визуально выделен.

---

# Отображение остатков

Под переключателем показывать компактный информационный блок.

Пример:

```text
Доступно:

Годный: 92
Брак: 8
Не проверено: 0
```

или:

```text
┌─────────┐
92
Годный
└─────────┘

┌─────────┐
8
Брак
└─────────┘
```

Использовать существующий стиль системы.

---

# Логика поля количества

Если выбран:

```text
Годный
```

Проверять:

```text
остаток годного товара
```

---

Если выбран:

```text
Брак
```

Проверять:

```text
остаток брака
```

# Валидация

Пример:

Выбрано:

```text
Брак
```

Количество:

```text
10
```

Доступно:

```text
6
```

Ошибка:

```text
Недостаточно брака на складе
```

---

Пример:

Выбрано:

```text
Годный
```

Количество:

```text
100
```

Доступно:

```text
80
```

Ошибка:

```text
Недостаточно доступного товара
```

---

# Бизнес-правила

BR-1

Отгрузка годного товара использует остаток годного товара.

---

BR-2

Отгрузка брака использует остаток брака.

---

BR-3

Товар со статусом:

```text
Не проверено
```

нельзя использовать в отгрузках.

---

BR-4

Нельзя смешивать годный товар и брак в одной строке.

---

BR-5

Тип остатка влияет на доступное количество.

---

# Изменение списка отгрузок

Добавить новую колонку:

```text
Тип
```

Варианты:

```text
🟢 Годный

🔴 Брак
```

Использовать badge.

---

Пример:

| Номер |   Клиент |      Тип | Количество |
| ----- | -------: | -------: | ---------: |
| 123   | ООО Тест | 🟢 Годный |         25 |
| 124   | ООО Тест |   🔴 Брак |          5 |

---

# Изменение логики остатков

Убрать отображение процента проверки из остатков.

Процент проверки относится только:

- к поступлениям
- к процессу приемки

Не отображать:

- в остатках
- в отгрузках

---

Новая структура остатков:

| Товар | Всего | Годный | Брак | Не проверено |
| ----- | ----: | -----: | ---: | -----------: |

Пример:

| Футболка XL |100|92|8|0|

---

# Фильтры остатков
