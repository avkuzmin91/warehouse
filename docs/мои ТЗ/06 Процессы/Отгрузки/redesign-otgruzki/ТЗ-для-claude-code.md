# ТЗ для Claude Code: карточка отгрузки по макетам (стиль рейсов)

> **Визуальный референс:** макеты в дизайн-проекте — `redesign-otgruzki/index.html`
> (10 артбордов). Перед началом приложи к Claude Code PNG нужного экрана
> (в канвасе: ⋯ на артборде → **Download PNG**) или открой HTML рядом.
> Карта артбордов → экранов ниже.

## Цель

Привести **карточку отгрузки** (создание, редактирование, закрытие) к тому же
визуальному языку, что и редизайн рейсов: **процесс = путь товара по складу**.
Главное изменение — **заменить горизонтальный статусбар (`ShipmentStepper`)
вертикальным «маршрутом отгрузки»** с ролями-владельцами, временем и маркером
«сейчас», а форму собрать из **фазовых блоков** с состояниями
active / locked / done.

## Рамки задачи

- Меняем **только фронтенд** слой `ui/` (презентация). **Бэкенд, `shipmentsApi.ts`,
  схему БД, статусы (`draft → packing → on_packing → relocating → awaiting_trip →
  shipped` / `cancelled`) и переходы НЕ трогаем** — данные те же.
- Названия статусов, полей и кнопок берём **как сейчас** (`SHIPMENT_STATUS_LABELS`,
  `SHIPMENT_STEP_DONE_LABELS`). Незначительные правки подписей — допустимы, но не
  переименовываем сущности.
- Соблюдаем слои и правила из `CLAUDE.md`: страницы → фичи → primitives,
  справочники только через `useLookups()`.
- Переиспользуем primitives (`Badge`, `Card`, `Icon`, `Button`, `Input`,
  `Combobox`, `DatePicker`, `NumberStep`) и токены из `ui/theme.css`. **Новых
  цветов/шрифтов не вводим.**
- **Шторки сохраняем как есть по логике** (`MoveToPackingDrawer`, `PackingDrawer`):
  меняем только визуальную обёртку под общий стиль. Логику перемещений/записей
  упаковки не трогаем.
- Делаем **инкрементально**: один экран = один PR.

## Переиспользуем компоненты рейсов

В `ui/features/logistics/components/` уже есть подходящие компоненты — **выносим
их в общий слой** (например `ui/features/shared/process/`) и переиспользуем,
а не копируем:

1. **`ProcessRail.tsx`** → обобщить под отгрузки: 6 фаз вместо 5, метки времени
   из `doc.ops` (как `getStepTimestamps` в текущем `ShipmentStepper`).
   **Заменяет горизонтальный `ShipmentStepper`.**
2. **`RoleChip.tsx`** → добавить третью роль `Нач. смены` (янтарный `--c-warning`,
   иконка `userCheck`). Текущие: `Менеджер` (индиго `--c-accent`),
   `Кладовщик` (синий `--c-info`).
3. **`PhaseBlock.tsx`** → без изменений: `state` = `active` / `locked` / `done`,
   accent зависит от роли.

## Маршрут отгрузки: роли по статусам

| Статус | Метка (текущая) | Метка «done» | Владелец (роль) |
|---|---|---|---|
| `draft` | Создание | Создан | Менеджер |
| `packing` | В плане | Передан на упаковку | Кладовщик |
| `on_packing` | На упаковке | Упакован | Нач. смены |
| `relocating` | Перемещение | Передан кладовщику | Кладовщик |
| `awaiting_trip` | Ожидает рейс | Готов к рейсу | Менеджер |
| `shipped` | Завершён | Завершён | — |

## Общий лэйаут карточки

- **Шапка** (`ShipHeader`): кнопка «назад» + `Badge` статуса + приоритет
  (`ShipmentPriorityControl`, как сейчас) + «сейчас у: `RoleChip`» + номер (mono)
  + контекстные действия справа.
- **Главная кнопка** = передача хода, с подсказкой «уйдёт … — статус „…“»:
  - `draft`: «Запланировать» → кладовщику;
  - `packing`: «Передать на упаковку» → нач. смены;
  - `on_packing`: «Передать кладовщику» → кладовщику;
  - `relocating`: «Готово к рейсу» (живёт в блоке раскладки, активна, когда весь
    годный/брак разложены);
  - `awaiting_trip` / `shipped`: главной кнопки нет, есть «Открыть рейс TR-…».
- **Сетка** `gridTemplateColumns: 'minmax(0,1fr) 332px'` (обязательно `minmax(0,…)`,
  иначе таблица состава распирает грид) — слева фазовые блоки, справа `ProcessRail`
  + контекстные панели (Готовность / Итого / Магазины / Рейс / Журнал).
- Прошедшие фазы — `done` (read-only сводка), будущие — `locked` с подписью
  «заполнит … после …». Весь путь виден уже при создании.

## Что реализовать по экранам

### Создание (`InventoryShipmentCreatePage`)
- Фазы: «Основная информация» (`active`, `CargoTypeToggle` + клиент + дата + ₽ + ТЗ),
  «Состав отгрузки» (`active`, таблица + «Добавить товар»), «Упаковка» и
  «Раскладка и рейс» — `locked`. Справа: `ProcessRail` (status `draft`),
  «Итого», чек-лист готовности (текущие `readyChecks`).

### `packing` — «В плане» (кладовщик)
- «Основная информация» — `active`, план редактируется (клиент залочен, как сейчас).
- «Состав · передача на упаковку» — `active`: колонка «Передача на упаковку» с
  «Передать» (открывает `MoveToPackingDrawer`, mode `transfer`) и возвратом.
- Справа: `ProcessRail` + чек-лист (текущие `advanceChecks` для `packing`).

### `on_packing` — «На упаковке» (нач. смены)
- «Состав · упаковка» — `active`: колонки «На упаковке» / «Годный / Брак» /
  «Действия упаковки» (кнопки «Внести упаковку» → `PackingDrawer`, «Подвезти» →
  `MoveToPackingDrawer` mode `replenish`). Справа панель «Итог упаковки».

### `relocating` — «Перемещение» (кладовщик)
- `RelocationPanel` остаётся: по каждой строке блоки «Годный»/«Брак» с местами
  хранения и `NumberStep`. Кнопка «Готово к рейсу» в шапке панели.
  Прошедшие фазы свёрнуты в `done`.

### `awaiting_trip` — «Ожидает рейс»
- Алерт (как сейчас) «Товар разложен… спишется при отправке рейса». Справа —
  карточка привязанного рейса (номер mono, статус, перевозчик). Состав — `result`
  (план + Годный/Брак, read-only).

### `shipped` — «Завершён»
- Read-only отчёт: «Основная информация» (с фактической датой и рейсом), состав
  `result`, панель «Итог отгрузки», полный журнал `doc.ops`.

### Шторки
- **`MoveToPackingDrawer`** и **`PackingDrawer`** — обновить только визуал под общую
  обёртку (шапка с заголовком/сабтайтлом, строка-статистика `StatStrip`, футер).
  Поля, валидации, история записей — без изменений.

## Порядок PR
1. Обобщить общие компоненты (`ProcessRail` на 6 фаз, `RoleChip` +`Нач. смены`),
   собрать `ShipHeader` + контекстные панели.
2. Заменить `ShipmentStepper` на `ProcessRail` во всех точках вывода карточки.
3. Карточка по статусам: `packing` → `on_packing` → `relocating` →
   `awaiting_trip` → `shipped`.
4. Экран создания (`InventoryShipmentCreatePage`).
5. Косметика шторок (`MoveToPackingDrawer`, `PackingDrawer`).

## Definition of Done
- Поведение и API не изменились; типы из `shipmentsApi.ts` те же.
- `ShipmentStepper` удалён/не используется; статусбар везде — `ProcessRail`.
- Только токены `theme.css`; пройдены `eslint` и `tsc`.
- Сетка карточки использует `minmax(0,1fr)` — таблица состава не распирает лэйаут
  ни на одном статусе.
