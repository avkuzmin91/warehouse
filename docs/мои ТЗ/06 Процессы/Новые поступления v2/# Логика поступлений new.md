# Логика поступлений с планированием

------

Архитектура:
Пришла машина клиента с товаром

Менеджер открывает систему

Переходит в интерфейс поступлений

Видит список всех поступлений:

Столбцы:

- Номер (имеется ввиду поступления - автоматически должен формироваться)
- Клиент 
- Дата
- SKU - автоматический подсчет количества SKU в поступлении
- Кол-во - автоматический подсчет общего количества товаров в поступлении
- Статус приемки
- Брак
- Статус проверки - Статус бар по проверке товара на брак

Сортировка по дате от большей к меньшей

Создает новое поступление по кнопке

Открывается карточка создания поступления

Заполняет обязательные поля:

Клиент - выбирает из справочника

Дата прибытия - выбирает с указанием времени

Заполняет необязательные поля

Поставщик - выбирает из справочника

ТТН / номер накладной - текст

Оператор - тот, кто создал приемку

Зона разгрузки - выбор из справочника

Стоимость логистики - в рублях

По кнопке добавить добавляет товары. При этом указывает обязательные поля:

1. SKU - выбирает из списка товаров
2. Цвет - если тип товара предполагает цвет
3. Размер - если тип товара предполагает цвет (установлен признак)
4. Количество

Нажимает "Сохранить черновик" - если приемка создается на будущее. Статус = "Черновик".
Нажимает "Принять товары" - если товар поступил. Статус = "Принят".

Спустя некоторое время происходит проверка брака при упаковке.

По завершении проверки брака:

Менеджер открывает соответствующую приемку и указывает  количество проверенного товара и количество брака

Макет к реализации предоставляется посредством выгрузки из клод дизайна
