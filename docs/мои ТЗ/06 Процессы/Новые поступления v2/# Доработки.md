Переработай статусную модель поступлений v2 и реализуй новую логику отображения этапов процесса.

Важно:

Не использовать старую модель статусов.

Не использовать:

- Черновик
- Создан
- Прибыл
- Проверен

Реализовать новый пошаговый статус-бар процесса.

Важно:

Это не просто статусы документа.

Это визуальные этапы процесса для пользователя.

Внутренние технические состояния могут отличаться.

Пользователь должен видеть понятный поток движения поступления.

------

Этапы статус-бара:

1. Планирование
2. Ожидается поступление
3. На проверке
4. Завершение

------

При создании новой карточки поступления:

этап "Планирование" должен быть активным.

Отображение:

● Планирование → ○ Ожидается поступление → ○ На проверке → ○ Завершение

Пользователь находится на этапе заполнения документа

Кнопки:

- Запланировать поступление
- Зафиксировать прибытие

------

После кнопки:

"Запланировать поступление"

этап "Планирование" считается завершенным

этап "Ожидается поступление" становится активным

Отображение:

✓ Запланирован → ● Ожидается поступление → ○ На проверке → ○ Завершение

------

После кнопки:

"Зафиксировать прибытие"

система должна:

1. создать операцию прибытия
2. сохранить дату и время
3. сохранить оператора
4. перевести документ на следующий этап

Отображение:

✓ Запланирован → ✓ Поступил → ● На проверке → ○ Завершение

------

Во время проверки:

этап остается:

✓ Запланирован → ✓ Поступил → ● На проверке → ○ Завершение

Дополнительно показывать прогресс по каждой строке поступления:

Проверено: X / Y

или прогресс-бар:

0%
35%
70%
100%

Прогресс не является статусом.

------

После кнопки:

"Завершить проверку"

отображение:

✓ Запланирован → ✓ Поступил → ✓ Проверено → ● Завершение

после завершения процесса:

✓ Запланирован → ✓ Поступил → ✓ Проверено → ✓ Завершен

------

Важно:

"Запланирован"

"Поступил"

"Проверено"

"Завершен"

это подписи завершенных этапов интерфейса.

Не хранить их как отдельные статусы базы.

Статус-бар является визуальным представлением процесса.

------

Не придумывать собственную логику.

Использовать строго эту модель.
