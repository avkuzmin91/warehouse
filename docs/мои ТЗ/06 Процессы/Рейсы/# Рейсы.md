# Логистика: Рейсы и операции рейсов

------

# 1. Цель

Реализовать модуль логистики для планирования и учета транспортных операций.

Модуль должен позволять:

- планировать транспорт
- объединять поступления и отгрузки в рейсы
- фиксировать факт прибытия и отправления транспорта
- учитывать затраты на логистику
- анализировать эффективность перевозчиков
- распределять стоимость логистики между клиентами

------

# 2. Архитектура

В системе уже существуют сущности:

- Поступление
- Отгрузка

Модуль логистики не заменяет их.

Добавляются новые сущности:

## 2.1 Рейс

Транспортная операция.

Отвечает за:

- перевозчика
- транспорт
- маршрут
- время
- стоимость

------

## 2.2 Операция рейса

Связующая сущность между рейсом и складскими операциями.

Позволяет прикреплять к рейсу:

- поступления
- отгрузки

Один рейс может содержать любое количество операций.

Одна операция:

- может принадлежать только одному активному рейсу

- может содержать множество операций

------

# 5. Статусы рейса

------

## Планируется

Создан менеджером.

Разрешено:

- редактирование
- добавление операций
- удаление операций

------

## Прибыл

Транспорт прибыл на склад.

Фиксируется:

- фактическое прибытие

------

## Обработан

Работы завершены.

Для поступлений:

- машина разгружена

Для отгрузок:

- машина загружена

------

## Закрыт

Внесены фактические расходы.

Рейс считается завершенным.

Редактирование запрещено.

------

# 6. Работа менеджера

------

## Создание рейса

Менеджер создает рейс.

Заполняет:

- перевозчика
- транспорт
- маршрут
- плановые даты
- плановую стоимость

------

## Добавление операций

Менеджер выбирает:

- поступления
- отгрузки

Из существующих документов.

Создание новых поступлений и отгрузок из рейса не предусмотрено.

------

## Закрытие рейса

После завершения работ менеджер:

- указывает фактические затраты
- закрывает рейс

------

# 7. Работа кладовщика

------

## Прибытие транспорта

Нажимает кнопку:

"Транспорт прибыл"

Заполняется:

- фактическое время прибытия

Статус рейса:

Планируется → Прибыл

------

## Завершение работ

После завершения погрузки/разгрузки:

Указывает:

- время окончания работ
- загруженность склада
- комментарий

Нажимает:

"Завершить обработку"

Статус:

Прибыл → Обработан

------

# 8. Логика поступлений

Поступления продолжают работать по собственной бизнес-логике.

Существующая цепочка не изменяется:

Ожидает поступления → Принят

------

Важно:

Разгрузка транспорта не означает приемку товара.

Возможна ситуация:

- рейс обработан
- машина уехала
- поступление еще не принято

Это корректное поведение.

------

# 9. Логика отгрузок

Отгрузки продолжают работать по собственной бизнес-логике.

Существующая цепочка не изменяется:

Ожидает отгрузки → Отгружен

------

Важно:

Загрузка транспорта не означает завершение отгрузки.

Возможна ситуация:

- машина загружена
- рейс обработан
- документы еще не оформлены
- отгрузка еще не подтверждена

Это корректное поведение.

------

# 10. Ограничения

------

## Для операций

Нельзя прикрепить:

- закрытое поступление к закрытому рейсу повторно
- отгрузку к нескольким активным рейсам

------

## Для рейса

После статуса "Закрыт":

- редактирование запрещено
- добавление операций запрещено
- удаление операций запрещено

# 13. Аналитика

На основе рейсов формируются показатели:

- количество рейсов
- стоимость логистики
- стоимость по клиентам
- стоимость по перевозчикам
- стоимость по маршрутам
- среднее время обработки транспорта
- количество опозданий
- загрузка склада по времени
- стоимость логистики на единицу товара
- стоимость логистики на клиента

------

# 14. Итоговая бизнес-схема

Менеджер
→ создает поступления и отгрузки

Менеджер
→ создает рейс

Менеджер
→ прикрепляет операции к рейсу

Кладовщик
→ фиксирует прибытие транспорта

Кладовщик
→ выполняет погрузку и разгрузку

Кладовщик
→ завершает обработку рейса

Менеджер
→ фиксирует фактические расходы

Менеджер
→ закрывает рейс

Поступления и отгрузки продолжают существовать как независимые сущности WMS и работают по собственным бизнес-процессам.
