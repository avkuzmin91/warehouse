# ТЗ для Claude Code: шторка «Привязать поступление в рейс» (черновик рейса)

> **Визуальный референс:** `redesign-reisy/Привязать поступление.html`
> (интерактивный макет: два режима шторки + черновик рейса на фоне).
> Перед началом открой его рядом или приложи PNG обоих режимов
> (демо-панель сверху-слева переключает «Привязать» / «Создать»).

## Контекст и рамки

- Это **доработка экрана `draft`** карточки рейса — блок «Поступления в рейсе».
  Сейчас там дропзона «Привязать поступление · или создать новое прямо в рейсе».
  Нужно, чтобы по клику открывалась **правая шторка (Drawer)** с двумя режимами.
- Меняем **только фронтенд** `ui/`. Бэкенд, схему БД, статусы и переходы — **не трогаем**.
- Соблюдаем слои и правила `CLAUDE.md` (§4–5): страницы → фичи → primitives;
  справочники только через `useLookups()`, не напрямую `getDictionary`.
- Переиспользуем существующий **`Drawer`** primitive (тот же, что `AddLineSheet`
  в «Поступлениях») и primitives `Badge`, `Card`, `Icon`, `Button`, `Input`,
  `SelectField`, `TimeField`, `Checkbox`, `EmptyState`. **Новых цветов/шрифтов нет** —
  только CSS-переменные из `ui/theme.css`.
- Источник данных по поступлениям/строкам — модель из ТЗ «Логика поступлений»
  (документ + строки + операции; статус строки «В плане» = `planned`).

## Поведение шторки

Drawer справа, ширина **500px** (≤ `100vw − 24px`), затемнённый backdrop, закрытие
по фону / Esc / крестику. Структура: **header → сегмент-переключатель → скролл-тело
→ закреплённый footer**.

### Header
- Иконка `inbox` в акцентном квадрате 34×34.
- Заголовок «Поступления в рейс», подзаголовок:
  `Рейс {trip.number} · черновик · {trip.origin}` (номер — mono).
- Крестик закрытия.
- Сегмент-переключатель (как `Segmented`): **`[Привязать существующее]`** /
  **`[Создать новое]`**. Default — `link`.

---

### Режим 1 — «Привязать существующее»

Тело:
1. **Поиск** (`Input` + префикс `search`, плейсхолдер «Поиск: клиент, номер
   поступления…»). Фильтрует список по `client` и `number`.
2. **Подсказка-контекст** (faint, иконка `alert`): «Показаны поступления «В плане»,
   ещё не привязанные к рейсам. Сверху — из того же пункта отправления.»
3. **Список кандидатов** (`CandidateReceiptRow`), мультивыбор кликом по карточке:
   - чекбокс, клиент, номер (mono), `{sku} SKU · {qty} шт`, дата прибытия (иконка
     `calendar`), `Badge` «В плане»;
   - если `receipt.origin === trip.origin` — зелёный тег «тот же пункт» (`pin`) и
     карточка поднимается **выше** в сортировке;
   - выбранная карточка — `--c-accent-bg` + рамка `--c-accent` + лёгкий ring.
   - empty: иконка `inbox` + «Ничего не нашлось» + намёк перейти в «Создать новое».

**Откуда список:** поступления-документы в статусе `planned`, **не привязанные ни
к одному рейсу** (`trip_id is null`). Тянуть через существующий хук
`useUnassignedReceipts({ status: 'planned' })` из `receiptsApi` — если такого нет,
**не выдумывай endpoint, спроси меня** (вероятно нужен фильтр `?unassigned=1`).

Footer:
- слева: «Выбрано: **N** · `{qty}` шт» (или «Ничего не выбрано»);
- справа: `[Отмена]` · `[Привязать (N)]` (primary, `disabled` при пустом выборе).
- Действие: мутация `attachReceiptsToTrip(tripId, receiptIds[])` из `tripsApi`.
  После успеха — закрыть, инвалидировать `useTrip(tripId)`, toast «Привязано: N».

---

### Режим 2 — «Создать новое»

Тело — мини-документ поступления (поля из «Логика поступлений» §4.1):

| Поле | Контрол | Обяз. |
|---|---|---|
| Клиент | `SelectField`/`Combobox` (`useLookups().clients`), иконка `user` | ✅ |
| Поставщик | `Input` | — |
| Дата прибытия | `TimeField` (datetime) | ✅ |
| ТТН / накладная | `Input` | — |
| Зона разгрузки | `SelectField` (`useLookups().zones`), иконка `pin` | — |
| Комментарий | `Textarea` (2 строки) | — |

Ниже — блок **«Ожидаемые строки»** (необязательно): кнопка `[Добавить строку]`,
каждая строка = `SelectField` SKU (`box`) + кол-во (mono, «шт») + удалить (`trash`).
Пустое состояние: «Строки можно добавить сейчас или дозаполнить на приёмке.»
Ограничения строк из §12 ТЗ: нельзя строку без SKU; кол-во ≥ 1; **SKU только
клиента документа** (фильтровать список SKU по выбранному клиенту).

Внизу — пояснение (`accent-bg`): «Поступление создастся в статусе «В плане» и сразу
привяжется к рейсу `{trip.number}`. Документ появится в разделе «Поступления».»

Footer:
- слева: индикатор готовности (✓ «Готово к созданию» / `alert` «Укажите клиента и дату»);
- справа: `[Отмена]` · `[Создать и привязать]` (primary, `disabled` пока не заполнены
  клиент и дата).
- Действие: `createReceipt({...form, lines, status:'planned'})` → затем
  `attachReceiptsToTrip(tripId, [newId])`. Если в API есть атомарный
  `createReceiptForTrip(tripId, payload)` — используй его. Иначе — две мутации
  последовательно. **Не придумывай endpoint** — если нет ни того, ни другого, спроси.
  После успеха — закрыть, инвалидировать `useTrip(tripId)` + список поступлений,
  toast «Поступление создано и привязано».

## Правила

- Привязка возможна **только в статусе `draft`** (дропзона и шторка скрыты на
  остальных статусах).
- Операции пишутся как события (`trip_op` «добавление поступления» / receipt-op
  «создание документа») — через существующие мутации, **без правок схемы**.
- Тач-таргеты ≥ 44px не требуются (это менеджерский desktop-экран), но контролы
  не мельче 34px высоты — как в макете.
- Закрытие шторки сбрасывает локальный стейт (выбор / форму).

## Definition of Done

- В черновике рейса дропзона открывает Drawer; оба режима выглядят как
  `Привязать поступление.html`.
- «Привязать» добавляет выбранные поступления в рейс и обновляет блок
  «Поступления в рейсе» + чеклист «Готово к передаче» без перезагрузки.
- «Создать новое» создаёт документ `planned` и привязывает его к рейсу.
- API и типы (`tripsApi.ts`, `receiptsApi.ts`) не изменены сверх согласованного;
  только токены `theme.css`; пройдены `eslint` и `tsc`.
