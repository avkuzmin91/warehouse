Ты — система генерации тестовых данных для складской системы.

Сгенерируй полный набор справочников и товаров с корректными связями.

------

## 🔹 1. Справочники

### 📁 Клиенты (30 записей)

- Только названия (без ООО / ИП / АО)
- Стиль: брендовые/фантазийные (“Северный Ветер”, “Лунный Лис”, “Город Света”)
- Без фамилий и инициалов
- Все названия уникальны

------

### 📁 Поставщики (60 записей)

- Формат:
  - ООО "Название"
  - АО "Название"
  - допускается ИП
- Более формальные названия
- Уникальные

------

### 📁 Размеры

Стандартный набор:

- XS, S, M, L, XL, XXL, XXXL
- 44, 46, 48, 50, 52
- 98, 104, 110

------

### 📁 Цвета (20 записей)

Популярные цвета одежды:

- черный, белый, серый, бежевый, коричневый
- красный, синий, зеленый, желтый и др.

------

## 🔹 2. Товары (120 записей)

Сгенерируй:

- ~60 одежда
- ~60 техника

------

## 🔹 3. Правила генерации товаров

Каждый товар должен содержать:

- `name`
- `type` (определяется автоматически: одежда / техника)
- `image_url` (реальная ссылка на изображение)
- `client`
- `supplier`

------

### 👕 Если товар = одежда:

- Обязательно:
  - `sizes` (из справочника)
  - `colors` (из справочника)

------

### 💻 Если товар = техника:

- `colors` — опционально (0–2 значения)

------

## 🔹 4. Связи (КРИТИЧНО)

### ❗ Обязательное правило:

- **КАЖДЫЙ клиент должен иметь минимум 1 товар**

### Как это обеспечить:

1. Сначала:
   - В каждый товар впиши 1 клиента
2. Затем:
   - Остальные товары распределяй случайно

------

### Дополнительно:

- Поставщики распределяются случайно
- Один поставщик может иметь много товаров

##  5. Важно

- ❌ Не использовать заглушки (“Товар 1”)
- ❌ Не дублировать данные
- ❌ Не нарушать правило “1 клиент = минимум 1 товар”
- ✅ Все изображения должны соответствовать товару
- ✅ Названия должны быть реалистичными
- ✅ Тип товара определяется автоматически
