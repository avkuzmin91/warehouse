## 🧠 Промпт: интерфейс клиента (личный кабинет)

Ты — система, реализующая пользовательский интерфейс складской системы.

Твоя задача — предоставить клиенту доступ **только к его данным**: остаткам, поступлениям и отгрузкам.

------

# 🔹 1. Роли и доступ

## 👤 Клиент

- Видит **только свои данные**
- Не имеет доступа к другим клиентам
- Не может изменять справочники

## 🛠 Администратор

- Управляет пользователями
- Связывает учетную запись с клиентом из справочника

------

# 🔹 2. Привязка пользователя к клиенту

### Логика:

- У каждой учетной записи есть поле:
  - `client_id`

### Поведение:

- При входе пользователя:
  - определить `client_id`
  - все данные фильтровать по нему

### ❗ Важно:

- Если `client_id` не назначен:

  - запретить доступ

  - показать сообщение:

    > "Обратитесь к администратору для активации доступа"

------

# 🔹 3. Основные разделы интерфейса

------

## 📦 1. Остатки

### Что показывать:

- Текущие остатки клиента

### Поля:

- Товар
- Тип товара
- Цвет (если есть)
- Размер (если есть)
- Количество

### Особенности:

- Группировка:
  - по товару
  - или SKU (товар + атрибуты)

### Фильтры:

- Тип товара
- Поиск по названию

------

## 📤 2. Отгрузки

### Что показывать:

- Все отгрузки клиента

### Поля:

- Дата
- Товар
- Атрибуты
- Количество

### Фильтры:

- Период
- Товар

------

## 📥 3. Поступления

### Что показывать:

- Все поступления клиента

### Поля:

- Дата
- Товар
- Атрибуты
- Количество

### Фильтры:

- Период
- Товар

------

## 📊 4. Сводка (дашборд)

### Метрики:

- Текущий остаток (суммарно)
- Поступления за период
- Отгрузки за период

### Визуализация:

- график:
  - приход vs расход
- топ товаров

------

# 🔹 4. Фильтрация данных (КРИТИЧНО)

Все запросы должны автоматически включать:

```
WHERE client_id = current_user.client_id
```

❌ Нельзя:

- передавать client_id с фронта
- давать возможность изменить фильтр
