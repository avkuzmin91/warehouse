## Контекст

Файл: `warehouse/frontend/src/ui/features/inventory/receiptDetail/views/ReviewView.tsx`

Это экран QC-проверки поступления (статусы `on_review` / `done`). Внутри — карточка «Товары» с таблицей строк. Сейчас таблица плоская, 11 колонок, три разрозненных поля «Место», у каждой строки и у каждого места — иконка-дискета (сохранить). Всё остальное на экране (KPI-блоки, «Основная информация», «Готовность», «Журнал операций», шапка страницы, степпер) — **не трогать**.

## Суть Варианта B

Три **группы колонок** с двухуровневой шапкой. Каждая группа = пара под-колонок **«Кол-во»** + **«Место»**, и каждая группа подкрашена своим фоном-тинтом:

```
                                    ┌── Принято ──┐ ┌─── Годен ───┐ ┌─── Брак ───┐
 •  Товар              План  Кол-во │ Место  Кол-во│ Место  Кол-во │ Место   Статус·расхождение   Действие
```

Главные принципы (ради них вся переделка):
1. **Пары вместо россыпи.** Количество и его место всегда рядом и под общим групповым заголовком. Сразу видно: *Принято → его место (на проверке)*, *Годен → место годного*, *Брак → место брака*.
2. **Дискеты убраны полностью.** Ни строчной кнопки «Сохранить без завершения», ни поштучных дискет у полей места. Никаких `<Icon name="save" />` в таблице.
3. **Живой учёт расхождений.** Недостача / излишек считаются на лету (в т.ч. для строк «в работе», предварительно), а не только после завершения.

---

## Маппинг полей (важно — не перепутать)

| Группа / под-колонка | Поле в коде | Поведение |
|---|---|---|
| **Принято · Кол-во** | `line.accepted_qty` (фактически прибыло) | read-only, моноширинный, жирный |
| **Принято · Место** | zone kind `'storage'` (`storage_zone_id/name`) | combobox, авто-сохранение |
| **Годен · Кол-во** | `draft.accepted` / `line.accepted` | stepper (−/число/+), read-only когда `isDone`/`isReadonly` |
| **Годен · Место** | zone kind `'good'` (`good_zone_id/name`) | combobox, авто-сохранение |
| **Брак · Кол-во** | `draft.defect` / `line.defect` | stepper, тон warning, read-only когда `isDone`/`isReadonly` |
| **Брак · Место** | zone kind `'defect'` (`defect_zone_id/name`) | combobox, авто-сохранение |
| **План** | `line.planned_qty` | read-only |

`processed = accepted + defect`. Отклонение строки считается **относительно «Принято»** (`line.accepted_qty`):

- `surplus  = max(0, processed − accepted_qty)` → «излишек»
- `shortage = max(0, accepted_qty − processed)` → «недостача»

## Конкретные изменения

### 1. Шапка таблицы — двухуровневая (`rowSpan`/`colSpan`)

Замени текущий одноуровневый `<thead>` на две строки. Структура колонок (слева направо):

- `<th rowSpan={2} style={{ width: 20 }} />` — точка статуса
- `<th rowSpan={2}>Товар</th>`
- `<th rowSpan={2} style={{ width: 50, textAlign: 'right' }}>План</th>`
- `<th colSpan={2}>Принято</th>` — фон `tintArr`, по центру, `borderLeft`
- `<th colSpan={2}>Годен</th>` — фон `tintGood`, цвет текста `var(--c-success)`, по центру, `borderLeft`
- `<th colSpan={2}>Брак</th>` — фон `tintDef`, цвет текста `var(--c-warning)`, по центру, `borderLeft`
- `<th rowSpan={2} style={{ width: 150, borderLeft: '1px solid var(--c-border)' }}>Статус · расхождение</th>`
- `<th rowSpan={2} style={{ width: 130 }}>Действие</th>`

Вторая строка `<thead>` — под-заголовки групп (каждый со своим тинтом и `borderLeft` на левой ячейке группы):
`Кол-во` (textAlign right) · `Место` — для Принято; то же для Годен; то же для Брак.

### 2. Тинты — объяви рядом с компонентом

```ts
const tintArr  = 'var(--c-bg-sunken)'
const tintGood = 'color-mix(in oklab, var(--c-success) 7%, var(--c-bg-elev))'
const tintDef  = 'color-mix(in oklab, var(--c-warning) 8%, var(--c-bg-elev))'
```

Применяй фон **инлайн** к каждой `<Td>` соответствующей группы (во всех строках tbody), а левой ячейке каждой группы добавляй `borderLeft: '1px solid var(--c-border)'`, чтобы границы групп читались.

### 3. Тело строки — порядок ячеек

Точка-статус → Товар (название + `mono` sku·color·size) → План → **[Принято: Кол-во | Место]** → **[Годен: Кол-во | Место]** → **[Брак: Кол-во | Место]** → Статус·расхождение → Действие.

- Степперы количества (Годен, Брак) — оставь существующую вёрстку степпера, просто перенеси в нужные ячейки; ширину можно сузить до ~92px, чтобы влезло в группу.
- Поля «Место» — combobox на всю ширину ячейки (`width: '100%'`), без кнопки-дискеты рядом.

### 4. Убрать дискеты

- Удали из таблицы **все** `<Icon name="save" />` и кнопки вокруг них.
- Колонку действий оставь с двумя состояниями: `isDone` → кнопка «Изменить» (`handleReopen`); иначе → кнопка `primary` «Завершить» (`handleCompleteClick`), `disabled` при `zoneBlocked`, с тем же `title`/подсказкой про место.

### 5. Живое расхождение в колонке «Статус · расхождение»

Сейчас surplus/shortage показываются только для `isDone`. Сделай их живыми и для строк «в работе»:

- `const processed = isDone ? (line.accepted + line.defect) : (draft.accepted + draft.defect)`
- `const base = line.accepted_qty ?? 0`
- `const surplus = base ? Math.max(0, processed - base) : 0`
- `const shortage = base ? Math.max(0, base - processed) : 0`
- Бейдж статуса оставь как есть (`Проверено` / `В работе` / `Не начато`). Под ним:
  - излишек → `▲ +{surplus} излишек`, цвет `var(--c-info, #3b82f6)`
  - недостача → `▼ −{shortage} недостача`, цвет `var(--c-warning)`
  - для непроверенной строки расхождение — **предварительное**: показывай с `opacity: 0.85` и `title="Предварительно — зафиксируется при завершении"`.
  - если `processed === base && base > 0` и строка не «не начато» → мелкое серое `= сходится`.

### 6. Подвал `<tfoot>` — пересобрать под новые колонки

`Итого` с разбивкой: `План {totals.planned}` · `Принято {totals.acceptedQty}` · `Годен {totals.accepted}` (цвет success) · `Брак {totals.defect}` (цвет warning, с %). Справа — суммарное расхождение через те же `▲ +N излишек` / `▼ −N недостача` (живые из `totals.surplus`/`totals.shortage`); если оба нуля — `✓ расхождений нет` серым. Логику `totals` в `reduce` можно оставить, но сделай surplus/shortage **живыми** (считать от `draft` для непроверенных строк, как в п.5), а не только для `isDone`.
