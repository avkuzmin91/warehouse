# 📊 ТЗ: Модуль визуальных отчетов по складу и клиентам

## 1. Общая цель

Реализовать страницу аналитики, отображающую данные по:

- поступлениям
- отгрузкам
- остаткам по клиентам

Интерфейс должен быть современным (dashboard / BI-стиль), с упором на визуализацию данных и минимальный текст.

------

## 1.1 Ограничение доступа (ВАЖНО)

📌 **Аналитика доступна только пользователю с ролью `admin`**

### Требования:

- доступ к странице отчётов имеют только администраторы
- для всех остальных ролей:
  - либо редирект на главную / 403 страницу
  - либо отображение сообщения:
     **“Доступ запрещён”**
- проверка роли должна выполняться:
  - на backend (обязательно)
  - дополнительно на frontend (для UX)

------

## 2. Структура страницы отчёта

### 2.1 KPI блок (верхняя панель)

Карточки:

- 📦 Всего поступило
- 🚚 Всего отгружено
- 🏷 Текущий остаток (по всем клиентам)
- 👥 Количество активных клиентов

📌 Требования:

- одна строка (адаптивно)
- крупные цифры
- минимальный текст

------

### 2.2 График динамики

**Тип:** line chart

- поступления по датам
- отгрузки по датам

📌 Требования:

- 2 линии:
  - поступления (зелёный/синий)
  - отгрузки (оранжевый/красный)
- X: дата
- Y: количество
- tooltip при наведении

------

### 2.3 Остатки по клиентам

**Тип:** horizontal bar chart

- сортировка по убыванию
- топ-10 / топ-20 клиентов
- tooltip: клиент + значение

------

### 2.4 Баланс по клиентам (опционально)

**Тип:** stacked bar chart

- поступления
- отгрузки

------

### 2.5 Топ клиентов

#### 🟢 Топ по отгрузкам

#### 🔴 Топ по остаткам

- сортировка по убыванию
- простая визуализация (bar / list)

------

## 3. Логика данных

- Всего поступило
- Всего отгружено
- Остаток
- Активные клиенты

------

## 4. Поведение интерфейса

- без перезагрузки страницы
- API загрузка данных
- skeleton loading при загрузке
- фильтры (если добавлены) должны обновлять все графики

------

## 5. UI требования

- стиль: clean SaaS dashboard
- карточки с мягкими тенями
- единые скругления (8–12px)
- минимум текста, максимум визуализации

### Цвета:

- поступления: зелёный / синий
- отгрузки: оранжевый / красный
- остатки: нейтральный серый / синий

------

## 6. UX требования

- понятность за 5–10 секунд
- tooltip на всех графиках
- отсутствие лишнего текста
- адаптивность:
  - desktop: полный dashboard
  - tablet: 2 колонки
  - mobile: 1 колонка

------

## 7. Технические требования

Рекомендуется:

- Chart.js / Recharts / ECharts
- grid layout
- API слой для данных
- role-based access control (RBAC)

------

## 8. Результат

Пользователь-администратор должен:

- видеть полную аналитику склада
- понимать динамику поступлений/отгрузок
- видеть структуру остатков
- быстро находить проблемные клиенты

# 🔎 ТЗ: Фильтры для MVP аналитики склада

## 1. Общая цель

Реализовать базовый набор фильтров для страницы аналитики (поступления, отгрузки, остатки по клиентам), который позволяет пользователю быстро менять выборку данных без перезагрузки страницы.

Фильтры должны влиять на все графики и показатели на странице.

------

## 2. Состав фильтров (MVP)

## 2.1 📅 Период (обязательный фильтр)

Фильтр по времени, применяется ко всем данным.

### Варианты:

- Сегодня
- Последние 7 дней
- Последние 30 дней (по умолчанию)
- Произвольный диапазон дат (начало / конец)

### Поведение:

- при изменении периода обновляются все графики и показатели
- при выборе произвольного диапазона появляется выбор даты начала и конца (используй всплывающее окно как в глобальном компоненте фильтра даты)

------

## 2.2 👤 Клиенты (обязательный фильтр)

Фильтр по клиентам.

### Варианты:

- Выбор одного или нескольких клиентов
- Поиск по имени клиента

### Поведение:

- можно выбрать одного или несколько клиентов
- если ничего не выбрано — считаются все клиенты
- влияет на все графики и показатели
- Использовать множественный селект

------

## 3. Общие требования к фильтрам

Использовать глобальный компонент с панелью фильтров

### 3.4 Сброс фильтров

Должна быть кнопка:

**«Сбросить фильтры»** 

### После сброса:

- период = последние 30 дней
- клиенты = все
- тип операции = все

------

## 4. Требования к интерфейсу

### 4.1 Расположение

- фильтры находятся сверху страницы, над показателями

------

## 7. Результат

После реализации пользователь должен:

- быстро менять период анализа
- фильтровать по клиентам
- видеть обновлённую аналитику без перезагрузки страницы
