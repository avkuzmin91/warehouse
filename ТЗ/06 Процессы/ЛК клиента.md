# ТЗ: Личный кабинет клиента

# 1. Назначение

Реализовать раздел личного кабинета клиента для просмотра:

- остатков товаров
- поступлений
- отгрузок
- товаров (справочник товаров клиента, только чтение)

Раздел предназначен только для клиентов и предоставляет доступ исключительно к данным конкретного клиента.

## Товары

Список и карточка товаров **только текущего клиента**. Используется тот же механизм списка и фильтрации, что и в основной системе (серверная фильтрация, синхронизация с URL), но без возможности создания и редактирования.

Маршруты:

```
/cabinet/products
/cabinet/products/{id}
```

Описание:

- в списке отображаются только товары, привязанные к `client_id` пользователя кабинета;
- фильтры совпадают с основным списком товаров (кроме выбора другого клиента — в ЛК он недоступен);
- карточка товара открывается **только в режиме просмотра**: поля только для отображения, без кнопок сохранения и без перехода в редактирование.

Ограничения:

- запрещено создание товаров;
- запрещено редактирование товаров;
- доступ к данным строго **read-only** через UI и API.

Серверная часть обязана отдавать записи только при совпадении `client_id` товара с клиентом сессии портала (см. эндпоинты `GET /client-portal/products`, `GET /client-portal/products/{id}`, `GET /client-portal/products/{id}/variants` и справочники для фильтров портала).

------

# 3. Доступ

## Роли

Доступ разрешен только:

```
client
```

------

## Ограничения

Клиент видит только:

- свои товары (в т. ч. в разделе «Товары» — только просмотр)
- свои остатки
- свои поступления
- свои отгрузки

Backend обязан фильтровать данные по `client_id`.

Frontend не является механизмом защиты данных.

# 6. Query State

Все list pages обязаны использовать единый Query State Pattern.

В URL должны храниться:

```
page
limit
search
filters
sort
```

------

## Пример URL

```
/cabinet/remains?page=1&limit=20&sort=sku_asc
```

Любое изменение фильтра:

- обновляет Query State

- filters очищаются

После реализации клиент должен иметь возможность:

- видеть свои остатки
- отслеживать поступления

# 20. Раздел «Сводка»

# 20.1 Назначение

Раздел «Сводка» предназначен для отображения агрегированной аналитики клиента.

Страница должна позволять клиенту:

- быстро оценивать текущие остатки
- анализировать поступления и отгрузки
- видеть динамику движения товаров
- отслеживать наиболее отгружаемые товары

Интерфейс должен визуально и архитектурно соответствовать странице:

```
Главная / Аналитика
```

с максимальным переиспользованием:

- FiltersPanel
- графиков
- date picker
- step selector
- action buttons
- layout pattern
