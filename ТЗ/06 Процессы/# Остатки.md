# Логика списка остатков

------

## 1. Цель

Обеспечить просмотр текущих **складских остатков товаров** с возможностью:

- контроля доступного количества
- анализа по товарам и вариантам
- сопоставления с поступлениями и отгрузками

------

## 2. Сущность: Остаток

Остаток — это **расчётное значение**, формируемое системой на основе:

- поступлений со статусом **«Принят»**
- отгрузок со статусом **«Отгружен»**

------

## 3. Формула расчёта

Остаток по товару/варианту:

→ **Остаток = Принято − Отгружено**

------

## 4. Принцип отображения

Каждая строка списка остатков соответствует:

- конкретному товару
- конкретному варианту (цвет + размер при необходимости)

------

## 5. Таблица остатков

⚠️ Ключевое требование:
структура таблицы **максимально совпадает с поступлениями и отгрузками**

------

### 5.1 Колонки таблицы

| Колонка  | Смысл                           |
| -------- | ------------------------------- |
| Артикул  | базовый артикул товара          |
| Название | название товара                 |
| Клиент   | клиент карточки товара          |
| Фото     | превью товара                   |
| Цвет     | вариант товара                  |
| Размер   | вариант товара (если применимо) |
| Остаток  | текущее доступное количество    |

------

### 5.2 Правила отображения

- если размер не используется → поле пустое или “—”
- если фото отсутствует → заглушка
- остаток всегда ≥ 0

------

## 6. Фильтры

Фильтры должны быть **аналогичны поступлениям и отгрузкам**:

1. Артикул
2. Клиент
3. Название товара
4. Цвет
5. Размер

------

## 7. Поведение данных

### 7.1 Обновление остатков

Остатки пересчитываются при:

- изменении статуса поступления → «Принят»
- изменении статуса отгрузки → «Отгружен»
- редактировании количества в этих сущностях

------

### 7.2 Ограничения

- отрицательные остатки запрещены
- система не позволяет отгрузить больше, чем доступно
- остатки не редактируются вручную

------

## 8. UX-логика

### Принцип:

Остатки — это **витрина состояния склада**, а не редактируемая сущность.

------

### Поведение интерфейса:

- только просмотр
- фильтрация и поиск
- отсутствие кнопок создания/редактирования

------

## 9. Согласованность интерфейса

Использовать патерны и глобальные компоненты

------

## 10. Резюме

Список остатков:

- отражает текущее состояние склада
- строится на основе поступлений и отгрузок
- имеет идентичную структуру таблицы с другими сущностями
- не допускает ручного изменения данных
