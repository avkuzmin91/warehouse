# 📦 INVENTORY RECEIPTS (ПРИЕМКА ТОВАРОВ)

------

# 1. Цель

Реализовать систему приемки товаров на склад.

Система должна позволять:

- создавать поступления товара
- редактировать поступления
- искать товар по параметрам варианта
- фиксировать количество поступившего товара
- вести список всех приемок

------

# 2. Сущность: Receipt

```
{
  id: string,

  client_id: string,
  product_id: string,
  product_variant_id: string,

  sku: string,
  color_id: string,
  size_id: string | null,

  quantity: number,

  comment: string | null,

  created_at: datetime,
  created_by: string,

  updated_at: datetime,
  updated_by: string
}
```

------

# 3. Логика товара (ВАЖНО)

## 3.1 Поиск варианта товара

При вводе данных:

- Артикул (товара)
- цвет
- размер (если применимо)

→ система ищет **Product Variant**

------

## 3.2 Правила поиска

### Тип = Одежда

Обязательные поля:

- SKU
- color
- size

------

### Тип = Техника

Обязательные поля:

- SKU
- color

⚠ size НЕ используется

------

## 3.3 Результат поиска

Если найден:

- подтягивается:
  - product_id
  - variant_id
  - название товара (readonly)
  - габариты (если есть)
  - фото товара (preview)

------

Если НЕ найден:

```
Товар не найден
```

------

# 4. CREATE RECEIPT

------

## 4.1 Маршрут

```
/inventory/receipts/new
```

------

## 4.2 Поля формы

### SKU

- input
- обязательное

------

### Цвет

- select (из справочника цветов)

------

### Размер

- select (только для одежды)
- hidden для техники

------

### Количество

- number
- обязательное

------

### Комментарий

- textarea
- optional

------

## 4.3 Поведение формы

При изменении SKU / color / size:

→ выполняется поиск варианта товара

------

## 4.4 Автозаполнение (read-only)

- название товара
- фото
- габариты (если есть)
- тип товара

------

## 4.5 Сохранение

```
POST /receipts
```

------

# 5. EDIT RECEIPT

------

## 5.1 Маршрут

```
/inventory/receipts/{id}
```

------

## 5.2 Поведение

- загрузка данных receipt
- возможность редактирования:
  - quantity
  - comment
  - SKU / color / size (пересчитывает variant)

------

## 5.3 Обновление

```
PATCH /receipts/{id}
```

------

# 6. RECEIPTS LIST

------

## 6.1 Маршрут

------

# 7. UI правило

- все через PageContainer
- FiltersPanel обязателен
- Table + Pagination
- Query State Management

------

# 8. Ограничения

- нельзя создавать receipt без найденного variant
- нельзя отправлять quantity = 0
- size обязателен только для одежды
