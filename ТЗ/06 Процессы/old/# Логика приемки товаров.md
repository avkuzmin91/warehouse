# Логика приёмки товаров

---

## 1. Цель

Обеспечить учёт поступления товара на склад: регистрация и изменение поступлений, подбор товара по параметрам варианта, количество и сопутствующие данные, просмотр списка поступлений с отбором по условиям.

---

## 2. Сущность поступления (Receipt)

В системе фиксируется операция приёмки: связь с клиентом (карточка товара), товаром и вариантом (цвет, при необходимости размер), количество, комментарий, дата приёмки, автор и время регистрации/изменений.

Детальная структура данных определяется моделью хранения; для пользователя важно, что каждое поступление однозначно привязано к найденному на момент сохранения варианту товара.

---

## 3. Логика товара и поиска варианта

### 3.1 Ввод для поиска

Пользователь задаёт:

- **Дата приёмки** — календарная дата не позже текущего дня (обязательно).
- **Артикул** — базовый артикул товара из справочника (обязательно).
- **Цвет** — значение из справочника (обязательно).
- **Размер** — для типов товара, где размер обязателен (одежда и аналогичные правила); для типов без размера поле не используется.

После изменения артикула, цвета или размера выполняется поиск соответствующего **варианта товара** (Product Variant).

### 3.2 Правила поиска

**Одежда (и типы с обязательным размером):** для однозначного результата нужны артикул, цвет и размер.

**Техника (и типы без размера):** достаточно артикула и цвета; размер не запрашивается.

### 3.3 Результат поиска

**Если вариант найден** — в форме отображается информационный блок (только просмотр):

- наименование товара;
- **клиент**, которому принадлежит карточка товара;
- тип товара (если есть);
- габариты;
- изображение (если есть), с пояснением, что фотография одна на все цвета модели.

**Если не найден** — сообщение «Товар не найден» (или запрос указать размер, если без него результат неоднозначен).

Сохранить поступление можно только при успешно найденном варианте и корректно заполненных обязательных полях.

---

## 4. Создание поступления

**Раздел:** создание нового поступления из меню складских операций.

### 4.1 Поля формы (порядок сверху вниз)

1. Дата приёмки  
2. Артикул  
3. Цвет  
4. Размер — только когда тип товара требует размер  
5. Количество — целое число не менее 1  
6. Комментарий — необязательно  

Далее — блок результата поиска (см. п. 3.3).

### 4.2 Действия

- **Принять на склад** — создание поступления при валидной форме и найденном варианте.  
- **Отмена** — выход к списку поступлений без сохранения текущего черновика.

---

## 5. Редактирование поступления

**Раздел:** переход из списка по записи поступления.

Загружаются данные выбранного поступления; доступно изменение тех же сущностей, что и при создании (включая дату приёмки, артикул, цвет, размер при необходимости, количество, комментарий). При смене артикула/цвета/размера выполняется повторный поиск варианта; сохранение возможно только при успешном совпадении.

Отдельный заголовок страницы в карточке формы не обязателен — достаточно навигации (хлебные крошки / общий контекст приложения).

**Сохранить** фиксирует изменения; **Отмена** возвращает к списку поступлений.

---

## 6. Список поступлений

**Раздел:** список операций типа «приход» на склад.

### 6.1 Таблица

Рекомендуемые колонки:

| Колонка    | Смысл |
|-----------|--------|
| Дата      | дата регистрации поступления |
| Клиент    | клиент карточки товара |
| Артикул   | базовый артикул товара (не SKU варианта) |
| Цвет      | |
| Размер    | |
| Количество | |
| Фото      | превью карточки товара, если есть |

Доступны сортировка по колонкам (где применимо) и переход к редактированию записи.

### 6.2 Фильтры

Порядок в панели фильтров:

1. **Дата** — диапазон дат по дате регистрации поступления (от — до).  
2. Клиент  
3. Артикул — текстовый поиск **только по базовому артикулу товара**, без учёта SKU варианта.  
4. Цвет  
5. Размер  

### 6.3 Действия

- создание нового поступления;  
- переход к редактированию выбранной строки.

---

## 7. Ограничения и правила целостности

- Нельзя сохранить поступление без найденного варианта товара.  
- Количество должно быть положительным целым.  
- Размер обязателен только для типов товара, где это задано правилами.  
- Дата приёмки не может быть позже текущей календарной даты.

---

## 8. Согласованность интерфейса

Экран списка и формы приёмки должны быть согласованы с остальными списками и карточками приложения: единые принципы подписей фильтров, таблицы и действий, чтобы пользователь не терял контекст при переходе между разделами.
