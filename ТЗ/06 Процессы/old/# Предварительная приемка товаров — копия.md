# Логика предварительной приёмки товаров (плановая приёмка)

------

## 1. Цель

Обеспечить регистрацию **планируемых поступлений товара** до фактической приёмки на склад:

- фиксация ожидаемого поступления
- контроль и проверка данных до приёмки
- последующая финализация с обновлением остатков

------

## 2. Сущность предварительной приёмки (Planned Receipt)

В системе создаётся запись планируемого поступления:

- не влияет на складские остатки
- может редактироваться до момента приёмки
- после приёмки становится финальной записью

------

## 3. Статусы

**Фиксированный набор:**

- **Ожидание приёмки** — создаётся сразу при добавлении записи
- **Принят** — после финализации

Других статусов нет.

------

## 4. Ключевое правило

❗ Плановая приёмка может быть создана **только для существующего товара и варианта**

- нельзя сохранить запись без найденного варианта
- логика полностью совпадает с основной приёмкой

------

## 5. Логика товара и поиска варианта

Полностью соответствует основной приёмке:

### Ввод:

- Дата приёмки (любая дата)
- Артикул (обязательно)
- Цвет (обязательно)
- Размер (если требуется типом товара)

------

### Правила поиска:

- Одежда → артикул + цвет + размер
- Техника → артикул + цвет

------

### Результат:

**Если найден:**

- отображается блок информации о товаре

**Если не найден:**

- сообщение «Товар не найден»
- сохранение невозможно

------

## 6. Создание плановой приёмки

### 6.1 Поля формы

1. Дата приёмки
2. Артикул
3. Цвет
4. Размер (если требуется)
5. Количество (≥ 1)
6. Комментарий (необязательно)

- информационный блок найденного товара

------

### 6.2 Действия

- **Сохранить**
  - создаёт запись
  - статус = **Ожидание приёмки**
- **Отмена**
  - выход без сохранения

------

## 7. Редактирование

Доступно только для статуса:

→ **Ожидание приёмки**

Можно изменять:

- дату
- артикул / цвет / размер (с повторным поиском)
- количество
- комментарий

------

## 8. Финализация (приёмка)

### Действие:

- **Принять на склад**

### Результат:

- статус → **Принят**
- фиксируется окончательное поступление
- обновляются складские остатки

------

### Ограничения:

- повторная приёмка невозможна
- редактирование после приёмки запрещено

------

------

## 10. Ограничения и правила

- Нельзя создать запись без найденного варианта
- Количество — положительное целое
- Размер обязателен только для соответствующих типов
- Дата ≤ текущей
- После статуса «Принят» запись неизменяема

------

## 11. UX-логика

### Статусы:

- **Ожидание приёмки** — активная работа
- **Принят** — финальное состояние

------

### Поведение:

- форма всегда валидируется перед сохранением
- нет “частичных” сохранений
- пользователь всегда работает с корректными данными

------

## 12. Согласованность интерфейса

- Поведение соответствует основной приёмке
- Единые паттерны форм, таблиц и фильтров
- Консистентные действия и статусы во всей системе

------

## 13. Резюме

Модель:

→ Плановая запись (Ожидание приёмки) → Принят

Даёт:

- контроль до фактической приёмки
- отсутствие “грязных” данных
- простую и понятную логику без лишних состояний
